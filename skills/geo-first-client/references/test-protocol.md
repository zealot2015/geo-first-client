# GEO可见度测试协议（零基础与真实项目通用）

## 1. 测试前冻结范围

记录：品牌标准名、别名、目标市场（中国内地/海外等）、测试平台、客户端形态（网页/App/API）、模型或版本（能看到才填）、联网/搜索模式、提问日期及时区。不同平台和客户端不得默默混合为一个分母。

## 2. 问题分类

- 场景题：用户只有问题，不预先知道品牌；例：「1000平米的仓库潮湿，选工业除湿机应重点看什么？」
- 对比题：按需求比较选择，不刻意加入目标品牌；例：「两种除湿方式的维护成本怎么比？」
- 操作题：如何完成任务；例：「如何计算仓库除湿量？」
- 品牌核查题：明确询问目标品牌，只用于**信息准确性**，不得进入无提示自然提及的统计。

第一轮建议10～20个中立问题，按真实业务扩展。来源可包括买家真实问询、公开问答、销售FAQ、行业论坛（只作题目发现，非搜索量事实）。

## 3. 最小原始字段

日期及时区、平台/模型、联网状态、问题ID/全文、回答全文、回答截图或稳定存档、品牌是否提及、是否明确推荐、出现次序、原文可点引用URL、引用是否核验、错误说法、是否为诱导题、备注。对于没有任何来源功能的平台记「未显示」，不能记成「引用不存在」。

## 4. 定义统计口径

提及率 = 提到目标品牌的有效**非品牌核查题**回答数 / 有效非品牌核查题回答总数。

明确推荐率 = 明确将目标品牌作为可选项建议的有效非品牌核查题回答数 / 同一分母。

自有来源引用率 = 有可核验的自有内容引用的**有效可观察引用回答**数量 / 可观察引用的有效回答数量（要解释排除了哪些平台/回答）。

事实准确率 = 被抽检事实中正确陈述的条数 / 可验证的事实陈述条数；证据不足时不报百分比。

若平台未显示引用机制，不能将其分母混入“引用率”。「AI没有推荐」可以被记录，「网站没有被抓取/收录」不能据此推断。

## 5. 可比复测

使用固定问题集和平台/模式；至少保留基线和复测各自的原答及截图；列出模型、时间、平台差异，分析可能的随机波动。必要时留出未优化的对照问题，但也不要凭一次前后对比宣称因果。

## 6. 统计脚本限制

`scripts/visibility_summary.py` 只做对本地CSV的**描述性汇总**，假设记录已人工核实，不能验证截图、网页是否真的存在；它会排除 `问题类型=品牌核查` 行（如果该列存在），否则输出警告说明无法自动识别诱导题。所有报告保留警告和有效分母。
